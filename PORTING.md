# Porting a subset of Kivy to Nimony (nimkivy)

nimkivy is a narrow port of Kivy 2.3.2 to Nimony, drawing with SDL3 instead of
OpenGL. The subset is in `SCOPE.md`. Within it, nimkivy behaves like Kivy, and
`ACCEPTANCE.md` says how that is checked. `LAYERS.md` splits the work into
layers. Each layer is given to one porter.

## Source of truth

- Kivy 2.3.2 source in `upstream/kivy` (read only, gitignored). Get it with
  `git clone --depth 1 -b 2.3.2 https://github.com/kivy/kivy upstream/kivy`.
  The Cython files (`*.pyx`) are only in this checkout, not in the installed
  wheel.
- Kivy's documentation, at kivy.org/doc/stable and in the docstrings, describes
  the behaviour. Kivy's tests in `upstream/kivy/kivy/tests` are the behaviour
  to keep. The ones listed in `ACCEPTANCE.md` are ported with each module.
- The running Kivy is the installed 2.3.2 at
  `/home/ageralis/Projects/philosykos-website/kiosk/.venv`, which has the same
  sources as `upstream/kivy`. What it produced is stored as test fixtures in
  `tests/fixtures/` (REDESIGN.md, Standalone); the Python scripts that made
  them are kept in `archive/` as provenance and are not run.
- `kivy/data/style.kv` holds the default canvases of the in-scope widgets
  (Label, Image, RelativeLayout, ScreenManager, ModalView). There is no kv
  language at run time, so these rules are ported by hand into each widget's
  module, and every kv binding becomes an explicit typed `bind`. Apps write
  their widget trees with `buildUi` (`buildui.nim`), kv's rules as a
  compile-time plugin.
- Copied files must stay identical to Kivy's: `data/fonts/Roboto-*.ttf` and
  `DejaVuSans.ttf` from `kivy/data/fonts`.
- The first user is the kiosk app at
  `/home/ageralis/Projects/philosykos-website/kiosk/app/ui.py` and `voice.py`.
  It is the reason for the subset. nimkivy does not depend on it.

imports only from modules above it, never from below, and never inside a
proc. Source paths are relative to `upstream/kivy/kivy/`, Nimony paths to

## How the code is written

- **Names:** Kivy's names in Nim camelCase: `sizeHint`, `onTouchDown`,
  `addWidget`, `scheduleOnce`, `texture_size` becomes `textureSize`. Types
  keep Kivy's class names (`Widget`, `BoxLayout`, `ModalView`). Option values
  are Nim enums named after Kivy's strings (`fitCover`, `halignJustify`), and
  `parseEnum`-style helpers accept Kivy's strings.
- **Objects:** widgets and other dispatchers are `ref object of` their Kivy
  base class. An overridable Kivy method (on_touch_*, add_widget, do_layout,
  collide_point, the default `on_*` handlers) is a `method`. Everything else is
  a proc.
- **Mixins:** Nim has single inheritance. ButtonBehavior is an object held by
  the widget (`PillButton = ref object of BoxLayout` with a `button` field).
  The widget's `onTouchDown`, `onTouchMove` and `onTouchUp` methods call
  `procCall` on the parent class where Kivy's MRO calls `super()`, and the
  button part's `touchDown`, `touchMove` and `touchUp` for the rest (phase 2:
  no closure).
- **Properties and events: typed, generated by the `properties:` plugin**
  (phase 2; REDESIGN.md). Each property is a typed field with its own typed
  observer list and accessors (`width`, `width=`, `bindWidth`,
  `unbindWidth`, `dispatchWidth`); each event a typed observer list,
  `bindE`/`dispatchE` and its default handler as a method. Kivy's semantics
  live in the order of observers and in ReferenceList and Alias
  dependencies, so the plugin generates them in Kivy's order. Nothing is
  looked up by name at run time: a wrong property or event name, or a
  callback of the wrong type, is a compile error. `bindP` returns a
  `Binding` that `unbindP` takes. Phase 1 (plain code, named property
  descriptors, `Value` boxing) was replaced step by step and removed in
  phase 2 step 6.
- **Kivy's kwargs:** constructors take no property arguments. The caller sets
  properties after `newX()`. This gives the same result once the clock has
  ticked, because layouts are triggered with a timeout of -1.
- **Simple, flat code:** plain procs, objects, seq, string and Table. No
  macros, templates or generics unless the code would be worse without them.
- **Comments:** a `##` doc comment on every exported proc. A `#` comment says
  why at every non-obvious step. Where code follows a Kivy function, a comment
  names the Kivy file and function.
- **Errors:** follow nimony-error-handling. A missing image, font or WAV file
  is a `nil` texture, font or sound plus a log line, as in Kivy, never a
  crash. An SDL init failure stops the app at start. Callbacks do not raise.
- **No workarounds:** write the natural code. Where the stdlib falls short,
  add a `# GAP:` comment and a Gaps row. New bugs are recorded with
  nimony-bug-reporting and go to `planetis-m/nimony-bugs-llms`.
- **Same behaviour as Kivy** where the stdlib and SDL3 allow, including Kivy's
  quirks (for example, observer order depends on when an alias was first
  bound). Differences go under Gaps.
- **Skills:** read nimony-porting, nimony-error-handling,
  nimony-nim2-differences, nim-style-guide, nim-doc-comments,
  nim-code-organization and nim-testing before writing. For layer 2, also read
  nim-c-bindings and nim-c-wrappers.

## Build and tests

- Never run two Nimony builds at once. Each build uses its own `--nimcache`.
- **Run everything:** `./run_tests.sh` (from anywhere). It builds every
  `tests/t*.nim` and `tests/traces.nim` in debug and in `-d:release` with
  `nimony c --mm:orc --path:src --nimcache:nimcache/<name>-<mode> -o:bin/<name>-<mode>`,
  runs them, and compares the traces and scenes with Kivy's through
  `bin/compare-<mode>` (`tests/compare.nim`). `NIMONY` overrides the Nimony
  checkout. No Python is needed.
- Build:
  `nimony c --mm:orc --path:src --nimcache:nimcache/<name> -o:bin/<name> <file>.nim`.
  `--mm:orc` is needed because widgets and their closures form cycles (see
  Gaps). SDL is linked with `{.passL: "-lSDL3 -lSDL3_ttf -lSDL3_image".}` in
  `sdl3/*.nim`.
- Tests: one `tests/t<module>.nim` per module, using `block` tests and
  `assert` (Nimony has no `doAssert`; `assert` stays on in release).
  `run_tests.sh` runs every `t*.nim` in debug and in `-d:release`. It exports
  `SDL_VIDEO_DRIVER=offscreen SDL_RENDER_DRIVER=software SDL_AUDIO_DRIVER=dummy`,
  so tests that open a window or an audio device are headless and
  deterministic; run a test by hand with the same variables. Tests run from
  the repository root and read fonts from `tests/assets/fonts/` (Source
  Sans 3 and Noto Serif, SIL Open Font License, licence files beside them).
- Scenes: `tests/scenes.nim <scene> ...` renders the same trees as
  `archive/reference/scenes.py`, into `tests/out/<scene>.png` and `.txt`,
  through the real Window. Then `bin/compare-<mode> tests/out <scene> ...`
  checks them against `tests/fixtures/scenes` (see ACCEPTANCE.md): the
  geometry exactly, the pixels within budget. `run_tests.sh` runs the scenes on SDL's OpenGL renderer
  (`SDL_RENDER_DRIVER=opengl`, through the offscreen driver's EGL), which
  matches GL's rasterization and supports Kivy's blend mode; the tests stay
  on the software renderer (Gaps).
- Geometry: `tests/fixtures/graphics_points.txt` holds the points, radii and
  normalised Line shapes Kivy computes, and the children of a Canvas after add, insert,
  remove and clear. `tvertex_instructions` and `tinstructions` compare with
  it.
- Traces: `tests/traces.nim` writes `tests/out/traces/*.txt`, which must equal
  `tests/fixtures/traces/*.txt` line for line (`bin/compare-<mode> tests/out
  --traces`).
- Fixtures: Kivy's outputs in the format of REDESIGN.md (Standalone);
  `archive/README.md` says how they were made.
- Whole stack: `tests/tshowcase.nim` drives `examples/showcase.nim`
  (run_tests.sh runs it on the OpenGL renderer). The example runs on its
  own from the repository root:
  `nimony c --mm:orc --path:src -o:bin/showcase examples/showcase.nim`.
- Profiling: `tools/profile.sh` (PROFILE.md); `VIDEO=x11` for a real
  window.
- Do not commit. The coordinator reviews and commits each layer.

## Gaps

These are the places where nimkivy is less accurate than Kivy, because
Nimony's stdlib or SDL3 lacks something or has a bug. They are left for
another day. The rows below are foreseen. A porter confirms each one where the
code meets it, adds the `# GAP:` comment, and edits the row.

## Design differences (not gaps: chosen, not forced)

- `core/image`: the texture cache by file name never expires; Kivy's Cache drops entries after 60 s. A kiosk loads a fixed set of photos, so keeping them is fine.
- `core/text`: a label's texture is filled at once, not on first draw; Label always refreshes after a change, so the result is the same.
- Font lookup searches only `data/fonts` (and registered paths), not the system font folders.
- `core/window`: Kivy's `WidgetBase` (from `uix/widget.py`) lives here, with what the window and the event loop need of a widget: the typed `parent` and `children` properties (`bindParent`, `bindChildren`), a `canvas` field (pass `canvas: newCanvas()` to the constructor), the events `touchDown`, `touchMove` and `touchUp` (`bindTouchDown`, `dispatchTouchDown`, ...) whose default handlers are the `onTouchDown`/`Move`/`Up` methods, and `getRootWindow`, `toWidget`, `toParent`, `toWindow`, `addWidget`, `removeWidget` as methods. `WindowBase` is a `WidgetBase`, so a widget's parent can be the window. Widget (layer 6) is a `HintedWidget` (a `WidgetBase` with the hints, below) and overrides these, except `getRootWindow`, whose base already is Kivy's Widget.get_root_window; it adds `toLocal`. `addWidget` takes `canvas: CanvasLayer` (`layerCanvas`, `layerBefore`, `layerAfter`) for Kivy's `canvas=None/'before'/'after'`. `WidgetBase` is a `ref object of RootObj`; build it with `T(canvas: newCanvas())`, then `initWidgetBase`.
- `core/window`: Widget's box (`x`, `y`, `width`, `height`, `pos`, `size`, `right`, `top`, `centerX`, `centerY`, `center`) and the size and position hints (`sizeHintX`, `sizeHintY`, `sizeHint`, `sizeHintMin*`, `sizeHintMax*`, `posHint`) are typed properties of `HintedWidget`, which the window reads, sets and binds; it skips a root widget that is not one.
- `core/window`: `posHint` is a `PosHint`: entries of an enum key (`phX`, `phRight`, `phCenterX`, `phY`, `phTop`, `phCenterY`, `phPos`, `phCenter`) and a number (a pair for `phPos` and `phCenter`), in the order the keys were given (a Python dict's order), equal to another with the same entries in any order, so an equal hint does not dispatch. `w.posHint = {phTop: 0.9}` sets numeric hints; `PosHint.add` sets any. The size hints read as `Opt[float]` (none is Kivy's None) and can be set from plain numbers too (`w.sizeHintX = 0.5`).
- `core/window`: the window's events are typed (`mouseDown(x, y, button, modifiers)`, `keyDown(key, scancode, codepoint, modifiers)`, `keyboard(...)`, `keyUp`, `requestClose(keyboard)`, `draw`, `flip`, `resize`, `preResize`, `close`, `motion(action, me)`); a mouse button is the enum `MouseButton`, modifiers a `set[Modifier]`, and a key without a character has the codepoint "" (Kivy's None). Kivy's `_size` and `_density` are `rawSize` and `density`; `screenshot`'s default name is `screenshot.png`, numbered `screenshot0001.png` as Kivy's `screenshot{:04d}.png`.
- `input/motionevent`: a provider gives the normalized position to `initMotionEvent(..., sx, sy)` and `move(sx, sy)`, and sets what else the event carries on its fields (an SDL finger's `pressure`, a mouse touch's `button` and `multitouchSim`) where Kivy passes them in `args` to `depack`. `profile` is a `set[MotionProfile]`, `button` a `MouseButton`, a provider's event a `(MotionAction, MotionEvent)` (`maBegin`, `maUpdate`, `maEnd`). `touch.ud` is `claimedBy`, the objects that took the touch as theirs (ButtonBehavior, the only user). The soft keyboard modes of `scale_for_screen` are out of scope and gone.
- `config`: `Config` is typed: `Config.kivy.exitOnEscape`, `Config.graphics.width` (`height`, `resizable`, `fullscreen`, `maxfps`, `multisamples`, `minStateTime`), `Config.input.mouse` and `mouseOptions` (Kivy's `mouse,<options>`). Kivy's fullscreen `1` and `auto` are `true`. `metrics`: `dpi2px` takes a `Unit` (`unitDp`, ...). `base`: `EventLoop.status` is a `LoopStatus`.
- `uix/widget`, `uix/layout`, `uix/screenmanager`, `utils`: where Kivy raises (WidgetException: adding a widget to itself, or one that has a parent; instantiating the abstract Layout; ScreenManagerException; ValueError for a bad hex colour) the program stops with a message that says what is wrong, without Python exception names or class reprs (`cannot add a widget that already has a parent`); these are programming errors (nimony-error-handling), and the tests check them by running the test program again. Layout is abstract through the `isAbstract` method: `Layout` returns true, and each layout that derives from it directly (BoxLayout, FloatLayout, AnchorLayout) overrides it to return false, where Kivy compares the instance's class; a new layout derived from `Layout` overrides it too.
- `uix/widget`: `walk` is an iterator, as Kivy's is a generator, but it collects the whole walk before it yields the first widget, so a change of the tree during the walk is not seen; with `loopback` it stops at the start widget, as Kivy's `walk` does. `widgetChildren` is an iterator too.
- `uix/widget` and the layouts: a widget's constructor makes the object, calls `initProps` once (for its own type, which sets the defaults of its base types too), then its `init` proc (`initWidget`, `initLayout`, `initBoxLayout`, ...), which sets up the rest; Kivy's `EventDispatcher.__init__` sets up every property of the class at once.
- `uix/layout`: the layout keeps the bindings of the trigger it binds on each child and unbinds them in `remove_widget`, where Kivy funbinds the same bound method by name.
- `core/window/window_sdl3`: `Window` exists from the start, but its system window opens when the event loop needs it (`EventLoop.ensureWindow`: `App.run` before `build`, `runTouchApp` with a widget), and it reads Config's size then. Kivy opens it when `kivy.core.window` is imported, which Kivy programs do after setting Config; a Nim program's code runs after every module is loaded. A metric read before the window opens (`dp`, `sp`) uses the defaults (dpi 96, density 1), where Kivy would open the window to read it.
- `core/window`, `base`, `app`: Kivy calls `stopTouchApp`, `EventLoop.quit` and `App.get_running_app()` from inside the window module (local imports). Here those modules come later, so `base` fills in the window's `stopTouchApp` and `quitEventLoop` hooks, `App` sets `Window.runningApp` (which `getRunningApp` reads) and the `pauseApp` and `resumeApp` hooks that dispatch its `pause` and `resume`, and the event loop removes the closed window from its listeners with a `close` observer.
- `uix/behaviors/button` (phase 2): ButtonBehavior (decision 4) is a properties object the widget owns (`w.button`, from `newButtonBehavior()` or a subclass's constructor: `initProps`, then `initButtonBehavior`), not a mixin: the properties `state` (the enum `ButtonState`), `lastTouch`, `minStateTime`, `alwaysRelease` and the events `press` and `release` are the button part's, not the widget's (`w.button.bindPress(...)`, `w.button.state`). A subclass of ButtonBehavior overrides `onPress` and `onRelease` as methods (Kivy's class `on_press`). The widget's touch methods call the parent class's method through `procCall` where Kivy calls `super()`, and the button part for the rest: `touchDown(w, t)` after the parent's down, `grabbed(w, t)` before the parent's move and up, `touchMove(w, t)` after the parent's move, `touchUp(w, t)` for the grabbed touch (button.nim's module doc has the three methods). The button part has no reference to its widget: each call passes it.
- `uix/label`, `uix/image` (phase 2): `properties:` blocks. The subclass recipe is the widget's: `Label(canvas: newCanvas())`, `initProps`, then `initLabel` (`initImage`). The core label is made in `initLabel`; each font property has its own typed observer that sets the core label's option and schedules a render (Kivy's `_trigger_texture_update` by name). `fontSize` defaults to `sp(15)`, resolved when the label is set up (the window is open by then), as Kivy resolves `'15sp'` per instance. `fontHinting` None is `hintingNone`; `halign`, `valign` (core/text's enums) and `fitMode` are enums only, so `parseHalign` and `parseValign` are gone. `textSize` is a `TextSize` (`Opt[float]` pairs) and can be set from a pair of numbers. Image's `source` defaults to "" where Kivy's is None, so setting "" on a new image does not dispatch; nothing is loaded either way.
- `app`: the default `build` returns nil where Kivy's returns a new Widget, because Widget comes after `app` in the module order. An app overrides `build`.
- `core/window/window_sdl3`: every SDL finger makes a touch on every platform (SCOPE.md), where Kivy uses SDL's fingers only on Android and iOS; SDL's mouse events made from touches are switched off (`SDL_HINT_TOUCH_MOUSE_EVENTS`) and ignored. The mouse makes touches as Kivy's mouse provider does, but without multitouch simulation: a right click ends on release.
- `base`: the postproc modules (double and triple tap, dejitter, retain touch, ignore list, calibration) are not ported, so `is_double_tap` and `is_triple_tap` do not exist.
- `core/window/window_sdl3`: `screenshot` draws the frame again and reads it before it is shown, because SDL's frame cannot be read after `SDL_RenderPresent`; the picture is the one Kivy reads from its GL buffer. It is saved as RGB, as Kivy does.
- `animation` (phase 2): an Animation moves typed tracks, `newAnimation([opacityTo(Widget, 1.0)], duration = .2)`, in Kivy's keyword order; a track reads its start value and sets the property through the typed accessors (`Track.capture`, `Track.advance`), and `propKey(Owner)` (a `TrackKey`) names a property for `stopProperty`, `cancelProperty`, `stopAll` and `cancelAll`. The transition is a proc only (`outBounce`; `transitionByName` is gone). `animated_properties` is `tracks` (`$track` is `Widget.opacity -> 1.0`). The events are `start(target)`, `progress(target, progress)` and `complete(target)`. A target is any object with the tracks' properties (`RootRef`), told apart by identity where Kivy keys `_widgets` by `uid`; a track started on an object without its property stops the program, where Kivy raises AttributeError. `Animation.stop_all` and `cancel_all` are `stopAll` and `cancelAll` (nil is Kivy's None); `runningAnimations()` is `Animation._instances`, in start order where Kivy's set has no order. `_update` skips a target stopped during the same step, where Kivy would raise a KeyError.
- `uix/screenmanager`: the default `transition` is a NoTransition, because SlideTransition (Kivy's default) is out of scope; `initScreenManager` sets it before anything observes it, as Kivy sets it before `Widget.__init__`. `transition` is an alias over a plain field, because a property's stored value is a field the object constructor must fill and a `TransitionBase` (not nil) has no default value; it dispatches when another transition is set, as Kivy's ObjectProperty does. `current` is an `Opt[string]` (none is None; `current = "name"` sets some), as are `next` and `previous`. `screens` is replaced by a new list on each add and remove (in-place mutation is out of scope), which dispatches as Kivy's ObservableList does. `switchTo(screen, transition)` takes only the transition; Kivy's other options are set on the transition by the caller. The screens' `name` bindings are kept by their `Binding`. The events are Screen's `preEnter`, `enter`, `preLeave`, `leave` and TransitionBase's `progress(progression)` and `complete`; Kivy's class handlers `on_complete` and `on_progress` are the `onComplete` and `onProgress` methods. Kivy's privates `_anim` and `_on_progress` are `anim` and `animProgress` (the fade_half scene freezes the fade with them, as scenes.py does).
- `uix/screenmanager`: ShaderTransition removes the old screen's canvas from the manager before the next frame, scheduled when the transition starts; Kivy schedules it from a Callback instruction during the first frame with the mix. Callback is out of scope, and the mix covers that canvas in the one frame where Kivy still draws it, so the picture is the same.
- `graphics/renderer`: `Fbo` draws again only when it or a child changed, as Kivy's Fbo; `FadeMix` is FadeTransition's shader as two texture copies with SDL_BLENDMODE_NONE and SDL_BLENDMODE_ADD, which every SDL renderer supports (LAYERS.md planned a custom blend mode, which the software renderer refuses).
- `uix/modalview`: Kivy's private properties `_is_open`, `_window`, `_anim_alpha` (with its handler `onAnimAlphaChanged`) and `_anim_duration` are the typed properties `isOpen`, `window`, `animAlpha` and `animDuration`; `_touch_started_inside` is the enum `TouchStart` (`startUnknown` for None, `startOutside`, `startInside`). The events are `preOpen`, `open`, `preDismiss` and `dismiss`. `open(animation)` and `dismiss(animation, force)` take Kivy's keyword arguments as parameters.
- `core/audio`: Kivy's abstract Sound and its SDL2 provider SoundSDL2 are one type, `Sound`, since there is one provider; `loadSound(filename)` is `SoundLoader.load` (no `register`), and Sound is not built directly (Kivy: "You should not use the Sound class directly"). `state` is the enum `SoundState` (`$state` is Kivy's string); `source` is "" for None, and setting it loads the file (Kivy's `on_source`, the `onSourceChanged` method). The events are `play` and `stop` (`bindPlay`, `bindStop`).
- `core/audio`: each Sound opens its own SDL audio stream on the default playback device when it loads, and closes it in `unload`; Kivy opens one SDL2_mixer device for all sounds in `mix_init`. SDL's audio starts on the first `loadSound`, as Kivy's mixer does. `play` puts the whole file, flushes the stream (without the flush a resampled stream never empties and the end is never seen) and resumes it; `stop` pauses and clears it. `length` is the WAV's frames over its rate; Kivy's is the mixer's resampled chunk, the same to within a frame (tone.wav: both 1.4019954648526076).
- `core/audio`: `volume` is applied as Kivy's `int(volume * 128)` of 128, clamped to 0 .. 255; Kivy's chunk volume is a Uint8, so a volume below 0 or of 2 or more raises OverflowError there (a property callback cannot raise here).
- `core/audio`: after SDL_Quit (Window.close) a Sound no longer touches its stream, which SDL destroyed, so `stop` and `unload` still work and dispatch; the next `loadSound` starts SDL's audio again, where Kivy's `mix_is_init` flag never does.
- Kivy's quirks kept: `App.run` dispatches `on_stop` again after `stop()`; `App._stop` removes every second root widget (it removes while iterating); `EventLoop.stop` also removes the window's finger provider, so a second `run` in the same process has no finger touches; `WindowSDL.set_title` shows the title without changing `Window.title`.

- `props` (phase 2): a callback gets the new value, not the instance (a closure captures the instance), and `bindP` is Kivy's `fbind`: it returns a `Binding` for `unbindP`, and there is no `bind` that skips a callback already bound. A property's comparison is its type's `==` (an ObjectProperty `comparator` is the type's own `==`; a `ref` compares by identity); `Opt[T]` is `allownone`, an enum an OptionProperty. A `refs` or `deps` name may be a property of a base type. An alias without `cache` dispatches on every change of a dependency; Kivy's does not when its getter returns None, which none of nimkivy's aliases can. Such an alias stores nothing, so its type may be a `ref` without a default (ScreenManager's `transition`).
- `props`: `initProps` binds the `handler`s of the base types first, then the type's own in name order; phase 1 bound all of them in one name order. Each handler is the first observer of its own property either way (after the eager alias links), so no observer order changes.
- `props`: Kivy's per-instance events (`register_event_type`) and properties reachable by name at run time do not exist (REDESIGN.md); nothing in nimkivy uses them.
- `buildui` (phase 2): kv's rules are a compile-time plugin over Nim code, not a language loaded at run time. A binding follows, as kv does, every `h.p` its expression reads that is a property, but of a chain `a.b.c` only `a.b` (kv rebinds each link); a read that is not a property is evaluated and not followed, and a binding that follows nothing is a compile error. `Type(args)` calls `newType(args)` with positional arguments only (`prop = value` in the parentheses is a property), so a component is a `newX` proc where kv has a class rule. The widgets are made first and every item applied after, so any item can name any `as` handle (kv resolves ids at the end of the rule); each widget's bindings and handlers are bound after its children are added and before it is added to its parent. A handler's `result` starts false (Kivy's None). `on prop:` binds a property's change (kv's `on_<prop>`).
- `core/text/text_layout`, `graphics/instructions` (phase 2): Kivy's `str.strip`, `lstrip` and `rstrip` are `stripUnicodeSpace(s, leading, trailing)` with the white space set Kivy's layout depends on (`UnicodeSpace`, not only ASCII); Kivy's list `insert` and `remove` on a canvas's children are `insertAt` (a negative index counts from the end, out of range is clamped) and `removeFirst`.

## Decisions (coordinator, 2026-11-21, owner: "pragmatic, roll with it")

1. Audio: WAV only through core SDL3; no SDL3_mixer. The kiosk's clips are WAV.
2. ModalView default background: a plain box (atlas images are out of scope).
3. Property system (rewritten in phase 2): typed properties and events generated by the `properties:` template plugin over a type section (REDESIGN.md, ROADMAP.md phase 2 decisions); no `Value`, no names at run time. A type plugin (`type T {.plugin.}`) once planetis-m/nimony-bugs-llms#336 is fixed. Phase 1's plain-code system (`event.nim`, `properties.nim`) is gone.
4. ButtonBehavior (rewritten in phase 2): a properties object the widget owns (`w.button`: `state`, `lastTouch`, `minStateTime`, `alwaysRelease`, events `press` and `release`), not a mixin (Nim has single inheritance); a subclass of it overrides `onPress`/`onRelease` as methods, and the widget's touch methods call `procCall` on their parent class and the button part's `touchDown`, `grabbed`, `touchMove`, `touchUp`, with no closure (Design differences, `uix/behaviors/button`).
5. Antialiasing: none for now; tracked as a GAP. Revisit after layer 7 when the kiosk screens can be compared.
6. `Label.shorten`: out of scope until something needs it.
7. Android: layer 10 starts as an investigation; failures are GAPs/bug reports, not workarounds.
8. Reference scenes are compared on SDL's OpenGL renderer (the tablet draws through its GPU with OpenGL ES); unit tests stay on the software renderer. (coordinator, layer 3 review)

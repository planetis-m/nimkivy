# Phase 2: the Nim-style redesign

The plan for ROADMAP.md's phase 2. Behaviour stays phase 1's: the same tests,
traces and scenes, adapted in syntax only, are the safety net. The two
plugins were prototyped first (`prototypes/`, `prototypes/run.sh`, debug and
release); what they showed decides the mechanism below.

## What the prototypes showed (Nimony `95afaa04`)

| Route | Result |
|---|---|
| **Type plugin** (`type Widget {.plugin.}`) that adds accessors to the declaring module | **Broken.** A proc the plugin adds cannot read the type's fields ("undeclared field"); one without a field access is written without a module suffix and a call from another module crashes nimsem. Filed: planetis-m/nimony-bugs-llms#336 (`bug-reports/09`). Repro: `prototypes/typeplugin/`. Also: a type plugin runs only in modules that *name* the type (`let w = newWidget()` does not trigger it), so a plugin that rewrites uses would miss modules. |
| **Template plugin** `properties:` over a `type` section | **Works**, debug and release: typed fields, typed observer lists, change-only setters, bounds, a list, a reference list with Kivy's observer order, events with default handlers as base methods, subclass default overrides, compile errors for wrong names. `prototypes/props/` (tests `tprops.nim`, 5 rejected programs in `bad/`; moved to `src/` and `tests/` in step 1). |
| **Template plugin** `buildUi:` | **Works**, debug and release: a 3-level tree, `as` handles, bindings to another object's and to a sibling's property, handlers with and without arguments, built once and kept current. `prototypes/buildui/` (`tbuildui.nim`, 3 rejected programs). |

Three Nimony limits shape the layout of a module that uses `properties:`:

- **#290** (commented with the plugin case): a type a module-level template
  or plugin declares cannot be named in a *later* signature of the same
  module. Declarations *inside* the block can.
- **#175** (commented with a new shape, open, fix in review): a method in a
  module other than its class's fails in shoggoth, or silently calls the
  base method.
- **#337** (new, `bug-reports/10`): a type declared by a module-level template
  that refers to itself through `seq` crashes shoggoth (`ref object`) or is
  undeclared in its own field (`object`).

Decision (pragmatic, owner's rules): properties are generated by the
**`properties:` template plugin**, with the type-section syntax a type plugin
would take, so switching to `type T {.plugin: "props".}` when #336 is fixed is
mechanical (drop the wrapper, add the pragma). It is not a type plugin: a
deviation of mechanism, recorded in PORTING.md, not of behaviour. Until #290
and #175 are fixed, a module's procs and methods that name its property types
go **inside** its `properties:` block (the plugin copies them after the
generated code); other modules use the types normally. Until #337 is fixed,
`WidgetBase.parent` and `.children` are written by hand with the same typed
observer lists (GAP).

## Properties

### Declaring

```nim
properties:
  type
    Widget* = ref object of WidgetBase
      x* {.prop.}: float = 0.0                      # Numeric
      width* {.prop.}: float = 100.0
      pos* {.refs: (x, y).}: (float, float)         # ReferenceList
      right* {.alias: (getRight, setRight), deps: (x, width), cache.}: float
      sizeHintX* {.prop.}: Opt[float] = some(1.0)   # allownone: Opt
      posHint* {.prop.}: PosHint                    # Object, its own `==`
      opacity* {.prop, handler.}: float = 1.0       # class on_opacity
      disabled* {.alias: (getDisabled, setDisabled).}: bool
    BoxLayout* = ref object of Layout
      orientation* {.prop.}: Orientation = horizontal  # Option: an enum
      padding* {.varlist: 4.}: array[4, float]         # VariableList
    Label* {.defaults: (sizeHintY: none(float)).} = ref object of Widget
      color* {.color.}: Rgba = [1.0, 1, 1, 1]          # Color: 3 or 4 values
    Button* = ref object of Widget
      press* {.event.}: proc ()
      touchDown* {.event.}: proc (touch: MotionEvent)

  method onPress*(b: Button): bool = ...          # methods of these types
  proc getRight(w: Widget): float = w.x + w.width   # alias getter/setter
```

Kind by pragma: `prop` (Numeric, String, Boolean, Object, List, Option: the
Nim type says which), `bounds: lo .. hi`, `refs: (a, b)`, `alias: (get, set)`
with `deps`, `cache`, `eager` (Kivy's `watch_before_use`), `color`,
`varlist: 2|4`, `always` (Kivy's `force_dispatch`), `handler` (the class's
`on_<prop>`), `event`. A field without a pragma is a plain field. All are in
`src/nimkivy/props.nim` (step 1); `refs` and `deps` may name properties of a
base type. A block that declares `method onE*(w: Owner; ...): bool {.base.}`
or `method onPChanged*(w: Owner; v: T) {.base.}` itself gives the class its
own default handler (Kivy's `on_e` and `on_p` methods); otherwise the
generated one returns false or does nothing.

### What the plugin generates, per property `p: T` of `Owner`

| Generated | What |
|---|---|
| fields `pStore: T`, `pObs: Observers[proc (v: T) {.closure.}]` (+ `pLinked`, `pStop`, `pValid` for refs and aliases) | the value and its typed observer list; no `Value`, no storage table |
| `p(w): T` | a field read (refs and alias: refresh first, as Kivy's `get`) |
| `` `p=`(w; v: T) `` | bounds check (stops the program with the message, as phase 1 stops on Kivy's ValueError), change check with `==`, store, dispatch a copy to the observers in bind order; refs: set each reference, then one dispatch; alias: call the setter |
| extra setters | `varlist`: from 1, 2 or 4 numbers; `color`: from 3 numbers (alpha 1) |
| `bindP(w; cb): Binding`, `unbindP(w; b)`, `dispatchP(w)` | typed callback; the handle unbinds; `dispatchP` dispatches the current value (Kivy's `property('p').dispatch(w)`) |
| `initP(w; v)` | set without dispatch, for constructors and `{.defaults.}` |
| `initProps(w)` | `initPropValues` (the base's, own defaults, overrides), then `linkEagerProps` (the base's, then own eager alias links), then `bindPropHandlers` (the base's, then own in name order): phase 1's `initEventDispatcher` order for every property's observers. Each chain ends at a no-op for `RootRef` in `props`, so the base may be a type declared without the block |
| refs and alias: `linkP`, `triggerP` | on first use, a trigger is bound into each dependency's observer list, so its place among their observers is Kivy's (phase 1 keeps the same lazy linking) |
| `handler`: base method `onPChanged(w; v: T)` | the class's `on_<prop>`; a subclass overrides the method |

Per event `e: proc (args)`: field `eObs: Observers[proc (args): bool]`,
`bindE`, `unbindE`, `dispatchE(w; args): bool` (observers last bound first
until one returns true, then the default handler), and the base method
`onE(w; args): bool` (Kivy's default `on_e`), which subclasses override.

A wrong property, event or default name, or a callback of the wrong type, is
a compile error (`tests/bad/`, checked by `run_tests.sh`).

### Binding

```nim
let b = label.bindWidth(proc (v: float) = label.textSize = (some(v), none(float)))
label.unbindWidth(b)
discard button.bindRelease(proc (): bool = app.goHome(); false)
```

Callbacks get the value, not the instance: a closure captures the widget.
(With the instance, a DSL or a subclass could not write the callback type:
proc parameters are invariant and the declaring class is not known at the
call site.) `Observers[F]` (`src/nimkivy/observers.nim`) keeps Kivy's
dispatch rules: bound during a dispatch, not called; unbound during it, not
called; unbinding marks the entry and the list is compacted when no dispatch
runs, so a dispatch allocates nothing (phase 1 copies the list each time).

### Animation

The plugin also generates, for each property of type `float`, a tuple or
array of `float` or `seq[float]`, a typed track:
`opacityTo(Widget, 1.0): Track` and its key `opacityKey(Widget): PropKey`
(an integer the plugin derives from `Owner.p` at compile time).

```nim
newAnimation([opacityTo(Widget, 1.0)], duration = 1.6).start(back)
a.stopProperty(w, opacityKey(Widget))
```

`Track` is a `ref object` with methods (start value, interpolate, apply), the
one place where dispatch is real: the tracks of one animation have different
value types. Instruction attributes (Color `rgba`, Translate `xy`, Rectangle
`pos`, ...) get hand-written tracks; the GAP "only Color and Translate can be
animated" can then be closed attribute by attribute. No plugin for
Animation itself.

## Pythonisms and what replaces them

| Today (phase 1) | Phase 2 |
|---|---|
| `Value` (variant boxing every property value and event argument), `toValue`, `toFloats` | typed fields and typed callbacks; gone |
| `DispatcherClass` name tables, `addProperty`/`addNumeric`..., `T(cls: TClass)` + `initX` | `properties:`; `newX()` / `initX(w)` call `initProps` |
| `getProperty`/`setProperty`/`fbind`/`bind`/`unbindUid` by name (Animation, layouts binding their triggers, the window reading root hints, Label forwarding font options, App title) | typed accessors and `bindP`; the hint properties move to `WidgetBase` (core/window) so the window reads them typed; Label binds each font property to its core label typed |
| event names as strings, `dispatch("on_press", args)`, `addEvent`, `setEventHandler`, `registerEventType` | `{.event.}`, `dispatchPress()`, default handlers as methods; `registerEventType` (per-instance events, unused) is dropped (GAP) |
| ButtonBehavior: `inherited` closure standing for `super()`, properties declared on the widget's class by name | ButtonBehavior is a properties object the widget owns (`w.button`; `state`, `press`, `release`); a subclass of it overrides `onPress`/`onRelease` as methods; the widget's touch methods call `procCall` on their parent class first, then `w.button.touchDown(w, t)`, so no closure |
| Animation targets by property name, `newAnimation({"opacity": 1.0})` (a kwargs bag), `transitionByName("out_bounce")` | typed tracks; transitions are procs only |
| `posHint` as `seq[(string, Value)]`, `setPosHint`, `{"top": 0.9}` | `PosHint = seq[(PosKey, PosValue)]` with enum keys, order kept (FloatLayout applies keys in order), its own `==` (dict equality) |
| `addWidget(..., canvas = "before")` | `canvas: CanvasLayer` enum |
| `touch.ud` keyed by `Value` | a typed set of objects (`touch.claimedBy`, the only use) |
| `_touch_started_inside` as int -1/0/1 | enum `TouchStart` |
| `Config.get("graphics", "width")` string sections and keys | typed `Config` fields (`Config.graphics.width`) |
| `"None"`/`"True"`/`"False"` in `$Value`, Python's repr in traces | `$Value` prints `none`/`true`/`false` and the fixtures are in Nim's format (step 0, below); `Value` itself goes in step 6 |
| `pyStrip`, `pyLstrip`, `pyRstrip`, `pyInsert`, `pyRemove` | Nim names saying what they do (`stripUnicodeSpace` with Python's whitespace set, which Kivy's layout depends on; `insertAt` with a negative index) |
| `quit "KeyError: ..."`, `"AttributeError: ..."`, `"ValueError: ..."` | most of these cases are compile errors now; the rest (`bounds`, a widget with a parent) say what is wrong without Python exception names |
| `parseHalign("center")` and other Kivy-string parsers | enums only |
| `Opt[T]` for Kivy's None | kept where None is a value (`sizeHint`, `textSize`, `ScreenManager.current`); `nil T` for a missing object |

Kivy's dynamic design that stays a GAP: per-instance events
(`register_event_type`); properties reachable by name at run time (kv,
`getattr`), which nimkivy has no use for; bindings in `buildUi` follow
`handle.prop`, not longer chains (kv binds `a.b.c`); the instance is not
passed to callbacks.

## `buildUi:`

```nim
buildUi:
  BoxLayout(orientation = vertical) as root:
    Header() as header
    Label(fontSize = sp(22)) as title:
      text <- topic.title & " (" & $topic.index & ")"
    PillButton(text = "Listen") as listen:
      on button.release:
        player.toggle()
      on touchDown(t: MotionEvent):
        idle.reset()
```

```
widget = Type(prop = value, ...) [as name] [: item+]
item   = prop = value            set once
       | prop <- expr            set now, and again when a handle.prop in expr changes
       | on [part.]event[(params)]: stmts
       | widget                  child, added in order
```

Expansion, in the caller's scope, nothing rebuilt later
(`prototypes/buildui/builduiplug.nim`):

1. `let name = newType()` for every widget in tree order (generated symbols
   for unnamed ones), so every handle exists before a binding uses it;
2. the `prop = value` items, in tree order (setters, so they dispatch);
3. `parent.addWidget(child)`, each child complete before it is added;
4. each binding: `w.prop = expr`, then for each `h.p` read by `expr`:
   `discard h.bindP(proc (v: typeof(h.p)) = w.prop = expr)`;
5. each handler: `discard w.bindEvent(proc (params): bool = stmts; false)`.

A wrong property or a binding to something that is not a property is a
compile error at its place. The prototype has all of this except `part.` in
`on part.event` (a path to an owned properties object such as `w.button`).

## Standalone: tests without Python (step 0, done)

- **Layout.** `tests/fixtures/`: `traces/*.txt`, `scenes/<scene>.txt` and
  `.png`, `graphics_points.txt`, `known-geometry-diffs.txt`, all made by
  Kivy 2.3.2. `tests/assets/`: the images, sound and fonts the tests, scenes
  and showcase read. `archive/`: the Python scripts that made them, the
  one-time conversion and a README (provenance only, never run).
- **Format.** Plain text, one fact per line, written the way Nim writes it:
  - `true`/`false`; `nil` for a missing object (`grabCurrent nil`); `none`
    for an empty `Opt` (`textSize = (300, none)`); a handler that returned
    Python's `None` is `false`;
  - numbers with 3 decimals (`formatFloat(x, ffDecimal, 3)`) where the
    traces and geometry print 3, and the shortest round-trip text elsewhere
    (`graphics_points.txt`: `$x`, the same digits as Python's repr);
  - tuples `(a, b)` (`(7,)` for one), seqs `@["a", "b"]`, `@[]`;
  - names are Nim's (`onTouchDown`, `isOpen`, `textureSize=`,
    `roundedRectangle`), enum values by their Nim names (`valignMiddle`);
    case and step labels (`rect_fraction`) stay as they are;
  - words logged as words are unquoted (`A state down`); the label trace
    shows each case as the Nim named arguments it sets, with Nim string
    literals (`text = "Hello", fontSize = 40 -> (93.000, 47.000)`).
  `tests/traces.nim` and `tests/scenes.nim` write this format; `$` of a
  phase-1 `Value` prints `none`/`true`/`false`. The Kivy-made files were
  converted once by `archive/convert-fixtures.sh`; `archive/README.md` lists
  the rules.
- **`tests/compare.nim`** replaced `compare.py`, with the same rules:
  geometry and traces line by line except the lines in
  `known-geometry-diffs.txt`; PNGs read with SDL3_image, a pixel differs when
  a channel differs by more than 24, budgets 0.5%, 3% for labels, modals and
  MSAA, 1% with JPEG; over budget, `tests/out/diff/<scene>.png`. Checked once
  against `compare.py` on the same outputs (archive/README.md): the same
  result for every scene and trace, the same pixel counts, the same failures
  on a broken copy.
- **Run:** `./run_tests.sh` (needs Nimony and SDL3, SDL3_ttf, SDL3_image; no
  Python, no `PY`). By hand, from the repository root:
  `bin/compare-debug tests/out <scene> ...`,
  `bin/compare-debug tests/out --traces [name ...]`, `--pixels <scene> ...`
  for pixels only, `--fixtures <dir>` first for other fixtures.

## Performance allowed in phase 2

Behaviour stays the same; PROFILE.md is the "before".

1. **Word-width cache** in `core/text/text_sdl3`: `getExtents` (997
   `TTF_GetStringSize` calls, 40% of all instructions, 197,000 per call) is a
   pure function of the font (file, size, style, hinting, kerning) and the
   word. A per-font table word -> (w, h), cleared when the font's hinting or
   kerning changes and bounded in size. It speeds re-renders of known words
   (Listen/Stop, a label laid out again); first renders at a new size
   (language change, resize) still measure.
2. **Typed properties** remove what PROFILE.md counts per drawn frame: 69
   name lookups (`getPropertyStorage`, `hashStrLong`), most of the 158
   allocations (boxed values, observer-list copies per dispatch, `seq[Value]`
   event arguments). The number of dispatches must stay the same (8.1 per
   drawn frame): a check that behaviour did not change.
3. Not changed: texture creation on first draw and SDL/EGL start-up are SDL
   and Mesa work; the slow first frames of a screen stay.

Step 1 notes: `tproperties` runs test_properties.py typed and replays the
first 44 lines of the `properties` trace (Widget's geometry and BoxLayout's
padding, the observer order with reference lists and aliases) on typed copies
of those properties; `tests/traces.nim` writes the `events` trace through a
`properties:` block; the prototype's tests are `tests/tprops.nim` (with

`{.untyped.}` template gives invalid C); `tproperties` writes around both in

Step 2 notes: `WidgetBase` is written by hand (#337: `children: seq[WidgetBase]`)

core/window cannot see Widget. Step 3 should move the geometry into

loop's are typed (`dispatchKeyboard`, `bindStart`, ...); App takes its class
